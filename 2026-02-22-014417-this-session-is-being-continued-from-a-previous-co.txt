  ---
  1. 数据采集 Bug 说明（直方图 0.0% 的原因）

  图中 "success rate 0.0%" 是误报，因为我写的轨迹记录器有个时序 bug：

  env.step(actions) 返回 obs ← 如果 done=True，这已经是 reset 后的新 episode
  状态
  robot.data.body_pos_w ← 读到的是 reset 后初始位置（EE 在空中很远处）
                                                                ↑
  不是成功瞬间的位置！

  所以每次成功终止后，记录的那一步 EE 坐标跳回起始位置，距离变成
  0.7m，掩盖了真正的 < 3cm 成功时刻。

  ---
  2. 两类 Episode 行为的对比分析

  ✅ 成功型（ep0、ep1、ep3、ep5）—— 弹道式快速抵达

  ep0: distance 0.778 → 0.031 → 成功 (25步, 0.83s)
  ep1: distance 0.758 → 0.030 → 成功 (23步, 0.77s)
  ep3: distance 0.607 → 0.032 → 成功 (28步, 0.93s)

  ---
  4. 根本原因定位

  原因 A：init_noise_std=1.0 造成不可控超调

  在 distance ≈ 8~10cm 范围内，每步理论修正量约为 scale × noise_std = 0.5 × 1.0 
  = 0.5 rad，对应末端位移远超 8cm。策略无法精细控制，只能反复超调。

  原因 B：success_bonus 梯度在 5~10cm 处接近零

  tanh(0.03/0.02) = tanh(1.5) = 0.905   ← 3cm 时奖励梯度
  tanh(0.06/0.02) = tanh(3.0) = 0.995   ← 6cm 时奖励梯度几乎一样！

  策略在 6cm 处与 3cm 处得到的梯度几乎相同 → 无动力继续靠近。

  原因 C：action_rate_l2 = -0.0001 太弱

  微弱的抖动惩罚无法阻止策略在目标附近持续输出高幅动作，极限环得以维持。

  原因 D：5秒 command 重采样触发"逃脱"

  从 ep4 数据可见：command 在 step 149 重采样后，EE 相对新目标距离变为
  0.224m，策略重新激活大动作模式，几步内就成功了（3.8cm）。这说明
  策略有能力快速到达，只是被困在了极限环里无法自主逃脱。

  ---
  5. 修复方案（优先级排序）

  # rsl_rl_ppo_cfg.py  ← 优先级 ★★★
  policy = RslRlPpoActorCriticCfg(
      init_noise_std=0.2,    # 1.0 → 0.2：降低动作噪声幅度
  )
  algorithm = RslRlPpoAlgorithmCfg(
      schedule="fixed",       # adaptive → fixed：防止 LR 衰减到 0
      learning_rate=1.0e-4,   # 稳定学习
      entropy_coef=0.02,      # 0.005 → 0.02：保持策略探索能力
  )

  # reach_env_cfg.py  ← 优先级 ★★★
  success_bonus = RewTerm(
      weight=5.0,
      params={"std": 0.05},   # 0.02 → 0.05：5cm 处仍有强梯度
  )
  action_rate = RewTerm(weight=-0.005)   # 0.0001 → 0.005：强力抑制极限环

  修复后预期效果：
  - init_noise_std=0.2 消除超调
  - std=0.05 使 6cm 处梯度比 3cm 处小 30%（而非现在的 0.5%）
  - action_rate=-0.005 使极限环代价高昂，策略主动收敛

  ---
  总结

  model_150.pt 的真实水平：约 67% 的 episode 快速成功（< 1秒），33% 的 episode 
  因奖励梯度消失被困在目标外 5~10cm 的极限环。你看到的"振荡"是 EE 
  绕目标的小圆圈运动，不是随机抖动，而是策略找到了一个局部稳定状态却无法跳出。根
  本修复需要重新训练，调整 success_bonus std 和降低 init_noise_std。
